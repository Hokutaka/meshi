# 要件定義

Version: 0.2

## 取引

| ID | 機能 | 仕様 |
| --- | --- | --- |
| R-01 | 取引登録 | 支出・収入、金額（整数円）、日付、カテゴリーを指定する。日付は当日を初期値とする。 |
| R-02 | クイック入力 | 金額とカテゴリーを入力して保存できる。 |
| R-03 | 編集・削除 | 登録済み取引の変更と削除確認に対応する。 |
| R-04 | 履歴 | 日付順の一覧と取引詳細を表示する。 |
| R-05 | 集計 | 月別の支出・収入・差引、およびカテゴリー別支出を集計する。 |

## 明細とマスタ

| ID | 機能 | 仕様 |
| --- | --- | --- |
| R-06 | 明細 | 取引ごとに任意件数の購入明細（名称・金額・カテゴリー）を追加できる。 |
| R-07 | 部分明細 | 明細合計が取引合計に満たない場合、差額を取引カテゴリーに集計する。 |
| R-08 | 商品マスタ | 商品名・既定カテゴリー・参考価格を登録し、明細入力時に呼び出せる。 |
| R-09 | 購入履歴 | 購入時の名称・金額・カテゴリーを明細に保存する。商品マスタ編集後も過去の購入情報を保持する。 |
| R-10 | 入力テンプレート | よく使う取引の金額・カテゴリー・名称を呼び出して編集できる。 |

実装順: R-01〜R-05を初期版、R-06〜R-10を次段階とする。

## データルール

- 取引はUUIDで識別する。
- 金額は正の整数円（64-bit）で保存し、支出と収入を別フィールドで区別する。
- 支出取引の明細合計は取引合計以下とする。
- 月間総額は取引合計から計算する。明細は分類・内容の分析に利用する。
- 支出カテゴリー別の合計は「明細の分類金額＋取引カテゴリーへ割り当てた残額」とする。
- 取引日（YYYY-MM-DD）と記録日時（UTC）を分けて保存する。
- 複数レコードの更新はDBトランザクションで処理する。

## 保存・保護

| ID | 機能 | 仕様 |
| --- | --- | --- |
| S-01 | DB保存 | Room + 暗号化SQLiteによる端末内保存。 |
| S-02 | 鍵管理 | DB暗号鍵をAndroid Keystoreで保護する。 |
| S-03 | アプリロック | BiometricPromptで端末認証・生体認証に対応する。 |
| S-04 | バックアップ | パスフレーズ暗号化したバックアップをユーザーが選択したファイルへ保存する。 |
| S-05 | 復元 | 暗号化バックアップの検証と復元。復元前に既存データの扱いを確認する。 |
| S-06 | マイグレーション | DBスキーマをバージョン管理し、既存データを保ったまま更新する。 |
| S-07 | パッケージ検査 | Release APKの権限、署名、バージョンをCIで検証する。 |

## 配布

- GitHub Releasesに署名済みAPKとSHA-256チェックサムを添付する。
- パッケージ名と署名鍵を継続利用し、versionCodeを更新ごとに増加させる。
- APK上書き更新後の取引データ保持をテストする。

## 初期版の完了条件

1. Android端末で支出・収入を保存・編集・表示できる。
2. 月別・カテゴリー別集計がテストデータと一致する。
3. アプリ再起動後も暗号化DBから履歴を取得できる。
4. 暗号化バックアップを別の初期状態から復元できる。
5. DB更新のマイグレーションテストが通る。
6. GitHub Releasesから配布した署名済みAPKを上書き更新できる。
